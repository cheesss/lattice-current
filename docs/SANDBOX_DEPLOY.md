# Sandbox Deploy Guide — Public Demo URL

Last updated: 2026-05-01

This guide walks through publishing a public read-only demo of Lattice
Current. The goal is a single URL anyone can click to see real (sanitized)
signal output without NAS access.

## What you ship

- **Static dashboard build** — `vite build` output (no DB required at boot).
- **Snapshot JSON** — generated by `scripts/build-public-demo-snapshot.mjs`,
  served from a static `/data/public-demo/` path or fetched at runtime.
- **Demo-mode API** — small Node service running with `LATTICE_DEMO_MODE=1`,
  serving `/api/demo/snapshot[/section]` and returning 403 on writes.

## Prerequisites

- Vercel account (or any Node host: Railway, Fly, Render).
- An up-to-date snapshot:
  ```bash
  node scripts/build-public-demo-snapshot.mjs --months=6
  ```
  This writes `data/public-demo/lattice-snapshot-<date>.json` (~5 MB at 6 months).

## Local dry run (read-only mode)

```bash
LATTICE_DEMO_MODE=1 node scripts/event-dashboard-api.mjs &
LATTICE_API_BASE=http://127.0.0.1:46200 npm run dev:vite
```

Open the dashboard. Confirm:

1. The bottom-right banner stack shows a "Demo data · read-only" warning.
2. `/api/demo/snapshot` returns the snapshot metadata (counts, attribution).
3. Clicking any review action returns 403 with `demoMode: true`.

## Vercel deploy

`vercel.json` already supports static + serverless. To enable demo mode on
deploy:

1. Build the snapshot in CI (or commit a static copy under `public/`):
   ```bash
   node scripts/build-public-demo-snapshot.mjs --months=6 --output=public/lattice-snapshot.json
   ```

2. Add to your Vercel project Environment Variables:
   ```
   LATTICE_DEMO_MODE=1
   LATTICE_DEMO_SNAPSHOT_PATH=public/lattice-snapshot.json
   ```

3. The API serverless functions (`api/[[...path]].js` etc) inherit the env
   and will refuse all writes. The dashboard auto-detects via
   `/api/demo/snapshot` and shows the demo badge.

## What the demo evaluator sees

- Top hero: "Today's top decision" — first validated event from the snapshot.
- Health pillars: pre-baked levels (data/pipeline/model/product) frozen at
  snapshot time.
- Hot Events: lane-separated list (validated / pending / watch / noise).
- Brief: each theme has structured 6-section content, including LLM
  narrative if present in the snapshot's cache.
- Trending: window-over-window article volume change.

What's blocked:
- All `POST /api/{review,watchlist,user-prefs,proposal-inbox/...}`.
- Real-time refresh (data is frozen at snapshot time; the badge says so).

## Refresh cadence

Re-run the snapshot script weekly via a cron / GitHub Action. Re-deploy with
the new file. Older snapshots can be archived.

## Acceptance

- External evaluator clicks `https://demo.lattice-current.app` (or whichever
  domain) and within 10 seconds sees a populated dashboard with the demo
  badge clearly visible.
- All actionable buttons either redirect to the live site (out of scope for
  the demo) or show a "demo mode is read-only" message.
